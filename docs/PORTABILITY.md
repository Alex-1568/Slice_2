# Portability status

## What was actually compiled and run

The current round-4 source was reviewed in an environment with GCC 14.2.0, Clang 17.0.0, and
CMake 3.31.6, but **Qt 6 development files are missing**, so a full CMake configure/build/CTest run
could not be performed. The isolated `IRandomProvider.cpp` compile and copy-operation negative probes
passed with GCC and Clang; the Python TSan-checker self-test passed. See `docs/VERIFICATION.md` for
commands and exact outcomes.

The following results belong to the **previous round-3 source tree only**, not the round-4 edits:

| Toolchain | Prior-round status | Notes |

## Static review checklist

| Concern | Result |
|---|---|
| GCC-only behaviour / compiler extensions | A source-scan test (`tst_security`) rejects `__attribute__`, `__builtin_*`, `__declspec`, `#pragma GCC/clang/warning`, `__int128`. Code builds with `-Wpedantic` (CMake `CXX_EXTENSIONS OFF`). |
| Linux/POSIX-only headers or APIs | The same test rejects `<unistd.h>`, `<sys/...>`, `<pthread.h>`, `<windows.h>`, `<dlfcn.h>`, `<fcntl.h>` under `src/` (the single exception is `infrastructure/random/OperatingSystemEntropy.cpp`, where platform headers belong). Threading uses `std::thread`/`std::shared_mutex` only. |
| Standard-library availability | `std::stop_token` **was** a real macOS/libc++ risk (confirmed: absent in libc++ 18 without `-fexperimental-library`) -> removed. `std::rotl` (`<bit>`) exists in MSVC 16.8+ and libc++ 9+. `std::shared_mutex` fine on supported macOS targets. |
| OS entropy backends | Linux `getrandom(2)` compiled and tested (incl. real-syscall fault injection). macOS `getentropy(2)` and Windows `BCryptGenRandom` are written to the documented APIs and **never compiled**; they are the highest-priority items to verify on those platforms. Other platforms fail to compile on purpose. |
| Filesystem behaviour | Slice 1 touches no files outside tests (tests read source files with `QFile`/`QDirIterator`). The `AR_SOURCE_DIR` define uses CMake forward-slash paths; a path containing quotes/backslashes would need escaping (not tried on Windows). |
| Integer assumptions | Double -> integer casts happen only after schema range validation. `qsizetype` -> `size_t` after a `>= 1` check. `-Wconversion` is clean on GCC and Clang. `uniformIndex` arithmetic is on `uint64_t`. 32-bit `size_t`/`qsizetype` were reasoned about, not executed; one test literal that would narrow on 32-bit was removed. |
| Floating point | `lgamma`/`log2` may differ in the last bits between libm implementations; all tests compare with 1e-9 tolerance and "exact" quality uses the same tolerance. Golden vectors are integer-only (RNG words, indices, strings) and were generated by an independent Python implementation. |
| Locale | Messages use `QString::arg` on integers (no locale grouping). |
| Unicode | Character classification/normalisation come from Qt's Unicode tables, which vary by Qt version. |
| Sanitizer flags | GCC/Clang flags in `cmake/Sanitizers.cmake`; MSVC gets `/fsanitize=address` only, **untested**. |
| Endianness / serialisation | None in Slice 1. |

## Known unknowns

MSVC warnings (`/W4`), Apple Clang's libc++ version, Qt 6.5-6.11 deprecations, and Windows
path/quoting behaviour of the test harness are unverified. A Qt-enabled runner must execute `tools/verify.sh debug` against the round-4 source and record the
result in `docs/VERIFICATION.md` before approval.
