# Public API audit — Slice 1.1 core, Slice 2 generators, GUI, and runtime plugins

Stability policy: **every contract below remains experimental** until the complete tree has been built and tested on a Qt-enabled runner. The identity generators, GUI, and runtime plugin integration now consume these contracts, but full compile/test verification is pending in this sandbox. Any change that forces third-party generators to be rebuilt must bump `domain::kGeneratorApiVersion`.

Historical note: Slice 1.1 round 4 changed the generator implementation hook and raised the API from 1 to 2. The runtime plugin integration introduced in the subsequent GUI/plugin slice raised it to **3**; `docs/PLUGIN_DEVELOPMENT.md` describes the current API v3 IID and ABI constraints.

## Per-contract review

| Contract | Ownership / lifetime | Thread safety | Exceptions | Cancellation | Invalid input | Qt types appropriate? | Size |
|---|---|---|---|---|---|---|---|
| `IRandomProvider` | `isCryptographicallySecure()` is **non-virtual** and set only through a `SecureAttestation` token that only `SecureRandomProvider` can create; every other provider is untrusted by default. Caller owns the provider; it must outlive every `GenerationContext` that references it. Copy and move construction/assignment are deleted so a derived provider cannot copy the attested base subobject. | Per implementation: `SecureRandomProvider` is stateless and thread-safe when its `ISystemEntropy` is (the OS source is); `DeterministicRandomProvider` is **not** (one per worker). | `nextUInt64` may throw `RandomSourceError`; `uniformIndex(0)` throws `std::invalid_argument`; broken source -> `RandomSourceError` after 256 rejections (bounded). | n/a | Regression coverage: type traits plus compiler-negative probes for copy constructor and assignment. | `CancellationToken/Source` | Token = shared view of the source's flag (`shared_ptr<atomic<bool>>`); outlives the source safely. | Fully thread-safe, lock-free, `noexcept`. | none | The mechanism itself. Per-source flag; no global state. | n/a | none | 2 tiny classes. |
| `GenerationContext` | Non-owning pointer to the provider; copyable value; make one per worker. | Immutable after construction; safe to share by const reference. | none | Exposes `isCancelled()`. | **No public way to accept a non-CSPRNG provider.** The switch is private; the only access is `testing::insecureContext()` in `testsupport/`, whose include path is exported solely by `ar_random_testing` (production targets cannot compile a call to it). Circumvention by deliberately declaring a friend-named struct stays possible for in-process code; the boundary targets accidents. | `ApplicationLimits` is plain `size_t`. | 4 accessors. |
| `IGenerator` | Registry holds `shared_ptr<const IGenerator>`; callers keep a pointer alive for the duration of a run. | `GeneratorResult` / `GenerationSummary` | Plain values. | Value types. | none | `status` carries Cancelled/StoppedBySink. | n/a | `QList<QJsonObject>`: fine for Slice 1; large batches should use the sink. | small |

| `ConfigurationSchema` / `FieldSpec` | Value types, copied into metadata. | Immutable after construction. | none | n/a | `validate()` is total: wrong types, ranges, unknown keys, too many keys (`maxParameterCount`) and over-long strings (`maxStringLength`) are reported, never thrown. ## Findings from this audit and what was done

| # | Finding | Action in 1.1 |
|---|---|---|
| F1 | `std::stop_token` is not available in libc++ 18 without `-fexperimental-library` (verified by compiling), so Apple/LLVM builds were at risk. | Replaced by the project-owned `CancellationToken/Source`. |
| F2 | `validate()` could not see runtime limits, and parameter-count / string-length ceilings did not exist. | `ConfigurationSchema::validate(params, limits)`, `maxParameterCount`, `maxOutputLength`; `validate()` applies the defaults, `generateInto()` applies the context's limits. `IGenerator::validate` keeps its signature on purpose (see "Deferred"). |
| F3 | `DeterministicRandomProvider` shipped inside the production RNG library. | Own library `ar_random_testing`; production targets link only `ar_random`; a source-scan test enforces it for `tools/` and `app/`. |
| F4 | `entropyBits`/`strength` conflated a configuration's search-space bound with password strength. | Replaced by `guaranteedEntropyBits` (lower bound), `searchSpaceBits` (upper bound), `entropyQuality`; no `strength` field; band derived from the lower bound only. |
| F5 | No plugin abstraction existed although the roadmap promised one. | `IGeneratorPlugin` + `kGeneratorApiVersion` + `registerPluginGenerators` (in-process test doubles only). |
| F6 | Exception behaviour of sinks undocumented. | Documented above. |
| F7 | Empty-parameters-means-defaults hazard. | Documented; test shows malformed JSON is detectable. |
| F8 | **(round 2)** `SecureRandomProvider` wrapped Qt's system generator, whose real behaviour includes hardware-RNG preference, silent fallback and ignored OS failure. | Replaced by fail-closed OS backends behind `ISystemEntropy`; Qt random classes banned under `src/`; fault injection incl. a real seccomp-denied `getrandom` (`docs/RANDOMNESS_AUDIT.md`). |
| F9 | **(round 2)** `requiresConfirmation(channel)` looked only at declared metadata and `handling()` let sensitive values through Export/Clipboard on the caller's honour. | Record-level confirmation decision; `ReleaseAuthorization` bound to a channel; default is redaction; four regression scenarios. |
| F10 | **(round 2)** `GenerationContext::forTesting()` lived in the production header. | Removed; private switch + `testsupport/` helper not visible to production targets. |
| F12 | **(round 3)** `isCryptographicallySecure()` was a virtual self-attestation; the public injection constructor let a test double make `SecureRandomProvider` claim security. | Non-virtual flag + construction-time `SecureAttestation` token (private ctor, one friend); injection constructor private behind `testsupport/`; `isOperatingSystemSource()` removed; build-time `static_assert`s; limits stated in `docs/RANDOMNESS_AUDIT.md`. |
| F13 | **(round 3)** Nested JSON in records: sanitisation depth unspecified. | Flat-record contract + whole-value handling + fail-closed treatment of objects/arrays; `validateRecord`; documented in `docs/SENSITIVE_DATA.md`. |
| F14 | **(round 3)** TSan class `KNOWN-QTTEST` accepted the watchdog name anywhere in a report. | The watchdog must be a racing party in a parseable data race, no project frames may appear, and the stack must match the known Qt Test teardown signature. Generic watchdog/worker races are `UNEXPECTED`. Self-test is a ctest entry. |
| F15 | **(round 4)** `IRandomProvider` copy/assignment copied the private attestation flag into derived providers. | Deleted copy/move operations on the base; added runtime traits and compiler-negative probes for copy construction/assignment. |
| F16 | **(round 4)** TSan could classify a generic watchdog race as environmental without a specific teardown stack. | Require the `QWaitCondition::~QWaitCondition` / `libQt6Core` and `QTest::qRun` / `libQt6Test` pairs on the same frames, in addition to the watchdog racing and no project frames. |
| F17 | **(round 4)** Flat-record contract was not enforced by the production generation boundary. | `generateInto()` is virtual-final and wraps `generateIntoImpl()` with a validated sink; all declared keys must be present, no extra keys or nested objects/arrays; batch errors/cancellation discard collected partial output. |
| F11 | **(round 2)** `verify.sh` ignored TSan failures (`|| true`). | `tools/check_tsan.py` + exit-status plumbing + `selftest` proving failures are detected. |

## Deferred / consciously not changed

* **Qt types in public interfaces** couple plugins to the host's Qt and C++ ABI. The runtime loader checks Qt's embedded plugin metadata and the generator API version, but `apiVersion()` cannot establish compiler/standard-library compatibility. Rebuild plugins against a compatible host SDK/toolchain. Replacing Qt types with `std::` types would add conversions everywhere; not done without a concrete need.
* **`IGenerator::validate` has no `limits` parameter.** Adding one (or a default argument on a
  virtual) was rejected as speculative; the context-aware checks run in `generateInto()` instead.
* **Unicode tables depend on the Qt version.** `QChar::category` and NFC normalisation come from Qt;
  a custom-character set that is valid under one Qt version could (rarely) be classified differently
  under another. Presets shared across Qt versions inherit that risk.
* No abstraction was added "for the future".


## Slice 2 integration notes

| Contract | Ownership / lifetime | Thread safety | Input / output safety |
|---|---|---|---|
| `INameDataProvider` / `NameDataset` | Provider is held as `shared_ptr<const INameDataProvider>` by a generator; `dataset()` returns a value copy. | Contract requires implementation to be thread-safe after construction. The built-in provider is immutable. | Built-in data is embedded/offline. Each generator checks dataset usability before generation. New built-in locale identifiers are added in the canonical `builtInNameLocales()` list and dataset; generator schemas derive from that list. |
| `TemplateEngine` | Static utility; no retained state. | No shared mutable state. | Small non-evaluating token grammar only; escaped braces, malformed syntax, unknown/missing values, and output bounds are checked. It does not perform I/O or evaluate expressions. |
| `IdentityGeneratorBase` | Stateless base; provider ownership is in concrete generator objects. | Concrete implementations are intended immutable after construction and use caller-supplied context/provider. | Common request/schema/runtime checks, cancellation, bounded uniqueness, RNG failure conversion, output-string size checking. The inherited final `IGenerator::generateInto()` validates metadata and each record before delivery. |
| Slice 2 output records | Returned as flat `QJsonObject` values. | Per call and caller-owned sink. | Exactly declared output fields; no undeclared fields or object/array values. Batch API is atomic with respect to returned partial records; streaming is not transactional. |

The Slice 2 compile/test status is intentionally kept separate in `docs/SLICE2_VERIFICATION.md`; no full C++ suite or mutation kill count is claimed for that source tree in the current sandbox.
